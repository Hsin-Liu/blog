# Self-Hosted Blog

A personal blog built with [Hugo](https://gohugo.io/) and the
[PaperMod](https://github.com/adityatelange/hugo-PaperMod) theme, deployed to
GitHub Pages via GitHub Actions.

- **Site**: <https://Hsin-Liu.github.io/blog/>
- **Repo**: <https://github.com/Hsin-Liu/blog>
- **Branch deployed**: `main`
- **Stack**: Hugo v0.162.1 (extended) · PaperMod · GitHub Pages

---

## Prerequisites

- **Hugo** `0.162.1` (extended) — required by PaperMod for SCSS processing.
  Install with `brew install hugo` and verify with `hugo version`.
- **Git** with submodule support (PaperMod is checked in as a submodule).
- A GitHub account with Pages enabled (see [Deployment](#deployment)).

> **Tip:** Match the version pinned in
> [`.github/workflows/gh-pages.yml`](.github/workflows/gh-pages.yml) locally so
> previews match what CI builds.

## First-Time Setup

```bash
git clone https://github.com/Hsin-Liu/blog.git
cd blog
git submodule update --init --recursive   # pull the PaperMod theme
```

## Project Structure

```
blog/
├── archetypes/
│   ├── default.md          # template for `hugo new posts/...`
│   └── micro.md            # template for `hugo new micros/...`
├── content/
│   ├── _index.md           # home page (front matter only)
│   ├── posts/              # long-form blog posts
│   │   └── hello-world.md
│   └── micros/             # short, tweet-style notes
│       └── hello-micro.md
├── layouts/                # custom layout overrides
│   ├── _partials/
│   └── index.html
├── static/                 # assets served as-is (images, favicon, etc.)
├── themes/
│   └── PaperMod/           # git submodule — do not edit directly
├── hugo.toml               # site config (TOML)
└── .github/workflows/
    └── gh-pages.yml        # CI: build & deploy on push to main
```

- `public/` is **gitignored** — it is generated by `hugo` and rebuilt in CI.
- `resources/_gen/` is also generated (image processing cache); safe to delete.
- `themes/PaperMod/` is a submodule; update it with
  `git submodule update --remote`.

## Configuration

All site settings live in [`hugo.toml`](hugo.toml). Common things to tweak:

| Setting                      | What it controls                                      |
| ---------------------------- | ----------------------------------------------------- |
| `baseURL`                    | Canonical URL (must match your GitHub Pages path)     |
| `title`                      | Site title shown in header / browser tab              |
| `[params].profile`           | Avatar, name, tagline, bio on the home page           |
| `[[params.social]]`          | Social-link icons in the profile box                  |
| `[params.homeInfoParams]`    | Hero text on the home page                            |
| `[markup.goldmark.extensions.passthrough]` | Enables `$…$` and `$$…$$` math blocks     |

## Writing a New Post

Hugo generates a file from the archetype and opens it in your editor:

```bash
hugo new posts/my-post-title.md
```

This creates `content/posts/my-post-title.md` with the
[`archetypes/default.md`](archetypes/default.md) front matter:

```toml
+++
date = '2026-06-01T14:57:01+08:00'
draft = true
title = 'My Post Title'
+++
```

### Front Matter Fields

| Field        | Purpose                                              |
| ------------ | ---------------------------------------------------- |
| `title`      | Post title (string, required)                        |
| `date`       | Publication date (ISO 8601, used for sorting)        |
| `draft`      | `true` hides it from the production build            |
| `tags`       | Array of tags — `tags = ['math', 'finance']`         |
| `categories` | Array of categories                                  |
| `math`       | `true` enables KaTeX rendering for the post          |
| `summary`    | Custom summary used in list views                    |
| `cover`      | Cover image (path under `static/` or page-bundle)    |

### Micro-posts

A second content type for short, tweet-style notes. They live in their own
section, have their own URL prefix, and render with a compact card style.

```bash
hugo new micros/your-thought.md      # scaffolds content/micros/your-thought.md
```

What the `archetypes/micro.md` archetype sets for you:

- `cover.hidden = true` — no cover image on the card or single page
- `ShowReadingTime = false`, `ShowWordCount = false`, `hideAuthor = true` —
  only the date is shown in the post meta
- `tags = []` — empty by default; add `['meta']`, `['math']`, etc.
- `draft = true` — flip to `false` when ready to publish

URL pattern: `/micros/<slug>/`. Micros also appear in:

- The home page sidebar widget (latest 5, in `layouts/_partials/micro-sidebar.html`)
- The dedicated listing page at `/micros/`
- The top nav (entry declared in `hugo.toml` under `[[menu.main]]`)
- The main `/index.xml` RSS feed (set `hiddenInRss = true` to exclude one)

Micro-posts share the `tags` taxonomy with long posts — a single tag cloud on
the home page mixes both.

### Images

Two patterns are supported. Pick by scope:

| Used in                    | Pattern                    | Path example                                  |
| -------------------------- | -------------------------- | --------------------------------------------- |
| One post only              | **Page bundle**            | `content/posts/my-post/cover.jpg`             |
| Shared across many posts   | **`static/`** directory    | `static/images/diagrams/payoff.svg`          |

**Page bundle** — turn the post file into a directory + `index.md`, then
reference images with a **relative path**:

```bash
mkdir -p content/posts/my-post
mv content/posts/my-post.md content/posts/my-post/index.md
cp ~/cover.jpg content/posts/my-post/
```

```markdown
<!-- content/posts/my-post/index.md -->
![Inline figure](figure.png)
```

Hugo can process bundle images (resize, format conversion) via
`.Resources.GetMatch`, and the file is deleted when the post is removed.

**`static/` directory** — drop the file anywhere under `static/`. Reference
with a **site-root path** (leading slash):

```markdown
![Logo](/images/site-logo.png)
![Diagram](/images/diagrams/payoff.svg)
```

No image processing — Hugo copies the file as-is. Use this for logos, favicons,
diagrams referenced from many posts, or any asset you don't need Hugo to optimize.

Cover image in front matter accepts either pattern:

```toml
[cover]
image = "cover.jpg"            # page bundle: relative to the post
hidden = false
```

```toml
[cover]
image = "/images/covers/intro.jpg"   # static/: site-root path
hidden = false
```

> **Tip:** micros set `cover.hidden = true` in the archetype, so the cover
> image field is effectively a no-op for micros — if you want an inline image
> in a micro, use a page bundle for that micro and reference it with a
> relative path.

### Math (LaTeX)

Goldmark passthrough is enabled in `hugo.toml`, so you can write:

```markdown
Inline: $E = mc^2$

Block:
$$
\int_{-\infty}^{\infty} e^{-x^2}\, dx = \sqrt{\pi}
$$
```

Add `math = true` to the post's front matter to load PaperMod's KaTeX assets.

## Common Commands

| Command                                              | What it does                                           |
| ---------------------------------------------------- | ------------------------------------------------------ |
| `hugo server`                                        | Live-reload dev server on `http://localhost:1313`      |
| `hugo server --buildDrafts`                          | Show drafts in the preview                             |
| `hugo server --buildFuture`                          | Show posts with a future `date`                        |
| `hugo new posts/foo.md`                              | Scaffold a new post from the archetype                 |
| `hugo --gc --minify`                                 | Production build (run by CI)                           |
| `hugo --gc --minify --destination ../public-test`    | Build to a custom output dir for inspection            |

### Drafts Workflow

1. `hugo new posts/draft-idea.md` — creates a draft.
2. Edit the file; leave `draft = true`.
3. `hugo server --buildDrafts` to preview.
4. When ready, set `draft = false` and push to `main`.

## Customising the Theme

- **Override a partial:** copy
  `themes/PaperMod/layouts/_partials/footer.html` to
  `layouts/_partials/footer.html` and edit the copy. Files in `layouts/`
  win over the theme.
- **Add static assets:** drop files into `static/` (e.g. `static/favicon.ico`
  → served at `/favicon.ico`).
- **Never edit `themes/PaperMod/` directly** — it is a submodule and your
  changes will be lost on the next `git submodule update`.

## Deployment

Pushes to `main` trigger
[`.github/workflows/gh-pages.yml`](.github/workflows/gh-pages.yml), which:

1. Checks out the repo **with submodules**.
2. Installs Hugo `0.162.1` (extended).
3. Runs `hugo --gc --minify`.
4. Uploads `./public` as a Pages artifact.
5. Deploys to the `github-pages` environment.

### One-Time GitHub Setup

1. Repo **Settings → Pages**.
2. **Source**: *GitHub Actions* (not *Deploy from a branch*).
3. Push to `main` — the workflow runs and publishes the site.

## Troubleshooting

- **Submodule is empty after clone** — run
  `git submodule update --init --recursive`.
- **`hugo: command not found`** — install Hugo (`brew install hugo`) and make
  sure your local version matches the workflow (`0.162.1` extended).
- **Math shows up as raw `$...$`** — make sure the post has
  `math = true` in its front matter **and** the `passthrough` block in
  `hugo.toml` is present.
- **Local build works but CI fails** — usually a submodule that wasn't
  pushed. Run `git submodule status`; any `-(dead)` entry means a missing
  `.gitmodules` reference. Commit and push `.gitmodules` and the submodule
  pointer in `themes/PaperMod`.
- **Changes to `themes/PaperMod` are gone after a pull** — expected; the
  theme is a pinned submodule. Override with files in `layouts/` instead.
